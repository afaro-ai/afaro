# v0.1.0

Phase 0. The first release, tagged on 2026-09-09.

Afaro walks a person through removing their own listing from US people-search brokers. This is the guided loop: one broker at a time, every submission approved in chat before it is sent, and each broker's flow described in a JSON file that was written from a screenshot of that broker's public opt-out page.

---

## What is in it

Numbers below are derived from the tree rather than remembered. `npm run validate` and `npm test` reprint them.

- **Nine broker manifests**, each validated against the schema, each with the capture it was written from committed alongside it and the date that page was read recorded in the file. Spokeo, Whitepages, FastPeopleSearch, TruePeopleSearch, Radaris, MyLife, PeopleFinders, Intelius, Nuwber.
- **Five skills**: orchestrator, exposure scan, removal verify, followup, and a scaffold for the California deletion request that is not implemented and says so.
- **A schema and a validator.** JSON Schema 2020-12, plus checks that live outside the schema because they depend on the filesystem or on a step's neighbours: provenance fields present and the capture on disk, a submit gate in front of every send, nothing filled after the last gate, nothing clicked between the last fill and its gate, one click per gate, the call that places a phone verification behind its own gate, and a search door that is a page rather than an internal endpoint.
- **52 self-checks**, 38 on the validator and 14 on the redaction sweep, including five fixtures marked permanent because each one encodes a bypass that was once possible.
- **A redaction sweep** with two git hooks, so no real person's details reach a tracked file or a commit message.
- **Guided mode only.** Every gate stops and waits for the person.

Seven of the nine manifests end on a `handoff` step. That is not an oversight: the rest of those flows sits behind a real listing or an emailed link, and nobody has captured those pages, so the manifest stops where the evidence stops and the person carries it from there. A handoff reports as handed off, never as submitted, and starts no recheck clock.

## What is verified, and by whom

**Checkable from this repository:** every manifest validates; every manifest names a capture that is present; every step selector's label is text on that capture, or the manifest says in its notes where the value came from instead; the checks pass.

**Maintainer testimony, which this repository cannot show you:** the skills were run on Claude Desktop with the Claude in Chrome extension, and three brokers were filed end to end on a real profile in guided mode during September 2026. Two of those listings were then gone from the sites' own searches; the third was filed with a recheck scheduled. A fourth run stopped itself with nothing filed when the site returned an error.

Run logs are local by design and are never committed, which is why those last claims are testimony. If that trade looks wrong, it is the same trade that keeps a person's details off this repository.

## What is not in it

- **No other runtime.** One runtime has been run. The manifests and the schema are data files with no runtime in them, and the skills follow the open Agent Skills specification, but nothing else has been tried and nothing else is claimed.
- **No supervised mode.** It is defined in the schema and the gate set so that adding it is behaviour rather than rework, and it is not implemented. A profile asking for it stops with a message.
- **No mailbox confirmations.** Several brokers finish through a link they email. The person opens their own mail and clicks it. Reading a connected mailbox is Phase 1.
- **No CAPTCHA solving, no bot-wall workaround, no invented values.** Those are not missing features. They are the shape of the thing.

## Open at this release

- **ClustrMaps has no manifest.** It was attempted across two sessions and its opt-out page could not be reached over HTTPS from the machine those attempts were made on. There is no guessed manifest for it.
- **PeopleFinders is filed by nobody yet.** A run stopped itself when the site returned its own error. It is queued for a retry with the person at the form.
- **Four captures are owed**, and each one is why a manifest stops where it does: Whitepages step 5 and its consent modal, and the form behind FastPeopleSearch's emailed link with its confirmation page.
- **No manifest carries a `name_page` block.** The schema supports one and no broker has earned it, because each needs two captures: the site's own A-to-Z bar, which names nobody, and the person's own name page from a real run, blanked. A pattern noticed in a search is a lead, not provenance.
